### 指标定义与逐规格结果

按单根、按规格分别匹配，TP 为同规格且长度在容差内匹配的根数；FP 为预测侧未匹配数，FN 为标准侧未匹配数。当前表使用 0 mm 容差。报告另将未匹配项中相对长度差不超过 5% 的配对诊断为“长度错误”；**5% 不是 TP 匹配容差**。长度错误会同时计入 FP 与 FN，增加仅计入 FP，缺失仅计入 FN。本轮长度错误为 0，剩余 6 根全部为增加项。

- Precision = TP / (TP + FP)。
- Recall = TP / (TP + FN)。
- F1 = 2 × TP / (2 × TP + FP + FN)。
- 本轮报告 Accuracy 数值与 TP / (TP + FP + FN) 一致，即 310 / 316 = 98.10%；未据此规定其他测试的通用 Accuracy 算法。本轮根数比例 min(310,316) / max(310,316) 也为 98.10%。
- 规格覆盖率与规格精确率按种类集合计算，与长度匹配容差无关；根数总量也不随长度容差改变。

## 仓库既有严格评分定义

用户提供的清单只在导出后离线读取。按“规格文本＋长度数值”逐根多重集完全匹配：

1. 基准每行一根；候选按最终单根数量展开。组合在导出时已展开，不再乘二。
2. 同一 key 匹配数量为 `min(基准数量, 候选数量)`；同规格同长度的多份副本分别计数。
3. 长度用十进制数值精确比较；5000 与 5000.00 相等，无额外舍入或毫米容差。规格文本不做后缀别名替换。
4. UNKNOWN 在候选分母中，不能匹配正确。错长通常同时产生一个候选未匹配和一个基准未匹配。
5. 型钢与 PL 是否纳入须明确；当前主指标仅型钢。材质未在输出中提供，不评分材质。
6. 此指标不验证逐位置实体身份；仅汇总数量接近不能证明匹配正确。

设基准 B、候选 C、匹配 TP，则 FP=C−TP，FN=B−TP：

- Precision = TP / C
- Recall = TP / B
- F1 = 2×TP / (B+C)

钢材种类指标另按规格集合交集计算，不检查长度、数量；种类 100% 和逐根 F1 较低可以同时出现。

### 首轮 UNKNOWN 的原因与重试边界

同一任务首次执行的第二阶段有 111/354 条 UNKNOWN。日志记录第二阶段 16 次 HTTP 429 并发限制、80 次 HTTP 402 余额不足，第三阶段另有 24 次 HTTP 402；这些计数包含重试。429 当时提示余额关联的账户并发上限为 14，是该账户在那次请求时的响应，不是服务商永久固定上限。

部分子代理未确定端点或缺少完整尺寸链，后续总代理/专家请求又因余额不足失败，最终保留未知长度。当前代码会将部分请求失败转为 UNKNOWN 或 FALLBACK，仍可能完成导出；任务 completed 仅表示流程结束，不保证全部请求成功。将账户不可用与识图不确定分开显示仍是待改进项，本轮文档整理没有更改该行为。

恢复 API 余额/额度后，若第一阶段有效，应从第二阶段重新执行，并让第三阶段使用新结果重新匹配。按账户实时可用并发调整任务覆盖设置，例如主 task 2、每视图请求 5，使第二阶段理论请求上限为 10；这只是运行配置示例，不修改默认 10×5 的调度规则，也不保证其他任务不占用账户额度。已完成后的第二阶段重跑会重新识别，不能按“只补失败请求”的费用预期操作。
