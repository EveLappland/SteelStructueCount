# 架构与数据流

当前产品使用一个原任务页面 `http://127.0.0.1:8120/`。新上传走固定标签流程；旧任务接口和历史数据继续兼容。两条后端执行链不能互换数据结构。

## 模块分工

| 层 | 入口 | 职责 |
| --- | --- | --- |
| 页面 | [index.html](../static/index.html)、[app.js](../static/app.js) | 上传、任务列表、三阶段切换、设置、操作与下载 |
| 新结果展示 | [fixed_stage.js](../static/fixed_stage.js)、[native_stages.py](../app/native_stages.py) | 将固定标签结果适配到原页面；台账只读 |
| HTTP 服务 | [main.py](../app/main.py)、[native_web.py](../app/native_web.py) | FastAPI、上传检查、任务队列、版本控制、持久化 |
| 第一阶段 | [run.py](../app/label_catalog/run.py)、[label_facts.py](../app/label_facts.py) | 视图定位、原生标签与轴面解析、高清图及事实包 |
| 第二阶段 | [label_length_workflow.py](../app/label_length_workflow.py) | 网格、总代理、专家、仲裁与长度契约 |
| 第三阶段 | [entity_workflow.py](../app/entity_workflow.py)、[entity_reduction.py](../app/entity_reduction.py) | 跨视图候选、匹配、守恒与归约 |
| 导出与审计 | [entity_report.py](../app/entity_report.py)、[audit.py](../app/audit.py) | Excel、JSON、来源对应、原始响应与事件日志 |

`app/label_catalog/` 是网页与 CLI 共用的正式第一阶段模块。`static/native_workflow.html` 只保留旧地址跳转；它不是另一套产品 UI。

## 三阶段交付

```mermaid
flowchart LR
  PDF[上传 PDF] --> S1[AI 定位与原生解析]
  S1 --> F[固定标签事实包与高清图]
  F --> S2[网格识图与本地长度计算]
  S2 --> O[逐标签观察台账]
  O --> S3[跨视图匹配与已有长度消歧]
  S3 --> E[实体、单根汇总与审计导出]
```

第一阶段把图上的标签转为可追溯身份：原文规格、当前所属面、邻近轴面候选、位置、轴面次序与原生尺寸文字。数量依赖“每根构件/组合都有标签”的输入假设，不是三维模型的全局真值。

第二阶段保留身份和数量。模型解释端部、拼接与尺寸文字的对应，返回文字 ID 和系数；程序计算数值。各视图独立观察，暂不跨视图去重。

第三阶段联合所有第二阶段输出。只匹配已有观察、选择已有长度，不能重新切段或生成尺寸表达式。单面观察和无候选观察直接保留；匹配失败也保留独立记录。组合件先匹配，最终单根导出才展开。

第一阶段事实包和高清图具有指纹；第二、三阶段进入调用前检查来源。图上坐标用于定位和关联证据，不当作真实毫米坐标。引用有效、算术正确与数量守恒不能证明尺寸的图形对应正确。

## 调度与阶段屏障

[task_slots.py](../app/task_slots.py) 管理两层独立许可：

- 新流程任务队列串行执行。
- 第一阶段最多并发 10 个文件 task；同一文件内部逐页定位。
- 所有文件第一阶段完成后，第二阶段最多同时处理 10 个视图 task。每视图独立最多 5 个代理请求，覆盖网格、总代理、专家、仲裁和请求重试。
- 单视图内部按依赖推进，不要求各角色同时调用；整体理论请求上限为 10×5，实际峰值需要日志实测。
- 全部第二阶段完成后，第三阶段按最多 10 个匹配组 task 调度，另受请求总预算约束。

上述数字是默认设置，可通过环境变量或 API 覆盖。PDF 提取与渲染使用 [native_pdf.py](../app/native_pdf.py) 的共享锁；API 等待在锁外，仍可并发。各文件写独立产物，由协调器记录任务状态，避免线程互相覆盖。

## 存储与恢复

| 位置 | 用途 |
| --- | --- |
| `data/native_runs.sqlite3` | 新流程任务状态、设置、阶段版本与历史 |
| `data/native_runs/upload-*/` | 上传源文件；不在单个任务证据 ZIP 的根目录内 |
| `data/native_runs/<id>/` | 各阶段结果、图片、请求记录、日志、导出及历史版本目录 |
| `data/jobs_v2.sqlite3`、`data/jobs/<id>/` | 旧任务兼容数据 |
| `tmp/` | 实验、准备、离线核对等本地数据，不是另一套产品服务 |

阶段结果目录带版本或尝试标识，不应假定永远是固定的 `stage_two/` 路径；通过阶段接口或任务记录取得实际位置。重跑使下游当前结果失效，保留旧文件与历史。

状态写入 SQLite；刷新页面可重新读取，服务启动时把未结束任务标为中断，不自动续付费调用。失败/中断的显式重试可复用通过输入与请求签名校验的已有结果；已完成任务重跑第二阶段则重新识别。API Key 等网页覆盖凭据仅存服务内存，重启后依赖 `.env` 或重新填写。

## 旧执行链的边界

旧 `/api/jobs` 仍由 [pipeline.py](../app/pipeline.py) 执行：页面用途筛选与目录 → 图像台账 → [完整 key 去重](exact-key-dedup.md) → 导出。其编辑、确认和重试 API 仍存在，不能称为只读接口。

新上传使用 `/api/native/runs/pdf`，当前固定标签台账只读。`tools/run_pipeline_test.py`、`tools/run_full_test.py` 调用的是旧 `/api/jobs`，不能作为新网页流程的全量验收。原页面可以展示两种历史任务，但不自动转换旧台账。

## 当前限制

- 钢材规格与轴面文字格式受现有解析器覆盖范围限制；扫描件不在当前流程范围。
- 第三阶段依赖已有所属面关系，标签缺失可能造成无法建立跨视图候选。
- UNKNOWN 与回退可以正常导出，但可能留下未知长度或重复。
- 网页上的旧“着色图实验”选项未接通新上传处理器；新流程当前使用原始高清 PNG。
- 当前不构建完整三维模型，不输出加工净长，也不以人工参考表改写结果。
