# 自动长度仲裁：设计与验证

2026-10-22，分支 `feature/automatic-length-arbitration`。

## 执行路径

第一阶段继续输出独立视图、完整面名、300 DPI 图和独立数量标准。第二阶段仍以网格 children / master 建立逐根台账。长度专家的有效表达式成为候选，不能直接覆盖台账。

`LengthArbitration` 是协调线程拥有的状态机，不自行开线程池或调用HTTP：

1. `length_evidence` 根据目标构件身份与标签位置请求补图，按端点、拼接、完整尺寸链合并上下文。只能访问本任务已上传的视图目录。
2. `length_verifier` 独立读取原图、网格与补图。工作包不包含 master / 专家的旧长度、旧端点与数值候选；也不包含证据调度代理的自由文本理由，避免其泄漏数值假设。
3. `length_arbiter` 接收所有候选和证据，逐ID裁决，允许根据新证据推导不同候选。返回端点、原始尺寸引用和表达式，本地完成计算与勾股，保留两位小数。
4. 补证/语义修订预算最多两轮。图示依据充分为 `SUPPORTED`，仍有歧义但自动采用可用候选为 `INFERRED`，无有效长度为 `UNRESOLVED`。不以人工继续为完成条件，不强行编造数值，不因待处理而删除构件。

证据与所有原始回复保留在 `grid_runs/.../<view_id>/arbitration/`，最终行保存 `length_arbitration`。网页和Excel分别展示裁决状态、原值、最终值与完整审计。字段通过后续台账验证仍保留。

所有角色、格式重试与总代理共用一个API请求队列；默认并发上限5，`.env` 的 `LLM_MAX_CONCURRENCY` 可配置，网页显式值优先。本地PDF提取、裁图与计算不计入API并发。
