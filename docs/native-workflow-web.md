# 固定标签流程网页

## 启动与操作

```powershell
.\.venv\Scripts\python.exe -m uvicorn app.main:app --host 127.0.0.1 --port 8120
```

访问 http://127.0.0.1:8120/ 。新版算法已接回原有阶段页面，旧地址 `/workflow?run=...` 自动返回 `/?job=...`。v0.4 的独立报告界面已撤回，历史任务与文件不删除、不转换。

网页和 CLI 共用 `experiments/pdf_label_tags/run.py:run`、`app/label_length_workflow.py:run`、`app/entity_workflow.py:run`，没有网页专用识别答案或独立的去重算法。

上传 PDF 默认自动完成一至三阶段。勾选“逐阶段暂停”会在每阶段完成后等待确认；勾选仅测试前两阶段则在第二阶段暂停。第一阶段先完成全部文件的视图目录与高清图，再进入第二阶段。原有目录、视图切换、高清图、钢材数量长度汇总、逐标签台账、阶段历史、导出与日志均在原页面显示。固定标签台账目前只读，编辑控件禁用；这是当前明确范围。

任务完成后，可在第二阶段点击“从第二阶段重新执行”：保留第一阶段，旧第二、三阶段目录留在历史中，新结果写入新版本目录；当前第三阶段及下载链接失效。旧版本操作返回409，重复确认不重复启动。失败或中断重试可复用校验通过的已完成阶段及匹配的模型响应，不覆盖已有完整结果。

原 `POST /api/native/runs/match` API 仍可只运行第三阶段；来源目录从 `tmp/label_lengths/` 和 `data/native_runs/` 发现，不接受任意文件路径。重复PDF视图、篡改标签、长度或图片在请求前拒绝。

每条输入标签保留独立身份。第三阶段仅匹配与选择已有长度来源，不新增尺寸表达式；同一视图的不同标签不能合并为一根。单面标签原样保留。UNKNOWN 和失败回退保留数量与原因，自动导出，无需人工审批。

思考强度默认 high；并发未填写时使用 `LLM_MAX_CONCURRENCY`，默认 5；第三阶段预算使用 `ENTITY_MAX_CALLS`，默认 24。预算耗尽时任务仍导出，页面明确显示回退数量。第三阶段不同于第二阶段的专家/仲裁，不进行自由重算。

任务之间串行，任务内请求并发。SQLite 状态及模型原始响应均落盘，浏览器刷新后可恢复显示。服务启动才执行中断恢复，普通模块导入不修改运行状态。任务完成、失败或中断后可重新执行，新建任务保留旧结果。相同请求编号重复提交不重复启动。

## 接口

- `GET /`：原有阶段网页；`GET /workflow` 重定向到原页面并保留任务ID。
- `GET /api/native/capabilities`：阶段接口能力；升级前服务不具备暂停功能时禁用新建任务，避免用户设置被静默忽略。
- `GET /api/native/sources`：可选第二阶段包及其视图、数量。
- `POST /api/native/runs/pdf`：上传PDF，Form 参数 `auto_run`、`stop_after_stage`、`reasoning_effort`、`max_concurrency`、`max_calls`；API覆盖凭据仅保存在内存。
- `POST /api/native/runs/match`：JSON 包含 `source_ids`、`request_id` 及上述参数。
- `GET /api/native/runs`、`GET /api/native/runs/{id}`：历史与状态。
- `GET /api/native/runs/{id}/stages/{number}`：适配原页面的只读阶段数据。
- `POST /api/native/runs/{id}/stages/{number}/approve`、`retry`：带阶段 `revision` 的确认和重跑操作。
- `POST /api/native/runs/{id}/rerun`：终态任务重新执行，JSON 包含新的 `request_id` 及设置。
- `GET /api/native/runs/{id}/logs`：运行日志。
- `GET /api/native/runs/{id}/files/{filename}`：限定在本任务目录的报告、高清图和导出文件。
- `GET /api/native/runs/{id}/evidence-download`：已完成任务的截图及证据包。

工作文件存于 `data/native_runs/{id}`，状态库 `data/native_runs.sqlite3`。这些文件和 `.env` 均被 Git 忽略，API Key 不持久化到状态或日志。一个数据目录只启动一个 Uvicorn 进程。

## 原页面接回修复与验收

v0.4 将新版算法放进独立 `/workflow` 报告界面，绕过了原来的阶段暂停、确认和重跑操作。这是界面集成遗漏，不能仅以识别结果可以下载就认为原网页功能已交付。

修复使用 `static/index.html`、`static/app.js` 的原有页面、任务列表、阶段页签和操作栏。`static/fixed_stage.js` 与 `app/native_stages.py` 只适配固定标签数据，不改模型识别、原始标签或长度。历史任务继续用旧 API，新任务用固定标签阶段 API，两者在同一任务列表展示。独立界面的脚本删除，旧 URL 保留任务ID重定向。

隔离目录使用已由真实 API 产生、重新校验通过的02第二阶段包，执行实际第三阶段工作流。因两个不同标高平面没有跨视图候选，本地独立保留90根，新增API调用为0。浏览器实际验证原页面阶段切换、45+45标签目录、2137×5613高清图、逐标签尺寸台账、等待确认→点击采用→完成、Excel与证据包下载入口，以及完成后第二阶段重跑按钮。重跑的版本校验、下游失效、旧导出保留、暂停策略和重复确认由HTTP/SQLite回归测试验证，没有用模拟模型回复替代测试。

203项Python测试及5项Node测试通过。台账编辑不在本次恢复范围内，页面明确只读，保存和JSON应用控件禁用，不保留看似可用的假编辑入口。

正在调用API的旧服务不能直接热换执行代码。结果查看可先接回原页面；阶段服务切换需等当前任务完成，或明确停止后保留已完成阶段和有效响应再续跑。能力检测在旧服务不支持阶段操作时禁用新任务创建，避免“逐阶段暂停”等选项被静默忽略。

## 离线评分

评分工具不会被模型工作流导入，参考表在识别结束后离线使用。它复用用户提供的 `tools/judge.py` 规格规范化和多重集匹配算法，UNKNOWN 保留在分母中，长度容差 ±1mm。不会按参考总数增删记录。

```powershell
.\.venv\Scripts\python.exe tools/evaluate_entity_run.py --result data/native_runs/<id>/stage_three --baseline <reference.xlsx> --logs-root data/native_runs/<id>
```

输出 `stage_three/evaluation/index.html` 与 `metrics.json`；刷新任务网页可打开该轮评分。规格+长度数量评分不能证明逐位置对应正确。既有原图核对表尚非用户最终确认的工程基准。
