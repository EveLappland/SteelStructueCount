# 网页操作指南

当前产品入口是 [8120 原任务页面](http://127.0.0.1:8120/)。旧地址 `/workflow?run=<id>` 会重定向到 `/?job=<id>`。同一页面兼容旧任务历史，新上传统一进入固定标签流程。

安装命令见 [README](../README.md)，并发、凭据和费用配置见 [配置说明](configuration.md)。

## 新建任务

1. 上传一份或多份可提取原生文字与矢量的 PDF。页面可包含多个平面或立面；概览、节点详图不作为目标建造视图。
2. 按需填写服务地址、模型、API Key 及两层并发；不填覆盖项则使用环境配置。
3. 默认自动执行三阶段。需要检查中间结果时勾选“逐阶段暂停”；只测试前两阶段时选择对应选项。
4. 点击“开始第一阶段”，在任务与进度区查看排队、当前阶段、模型等待与失败原因。刷新页面后可从已有任务列表恢复查看。

思考强度默认 `high`。当前界面保留的“着色图实验”选项未接入新上传链，新流程仍使用原始高清 PNG。

## 阶段展示

| 阶段 | 可以查看的内容 | 数量含义 |
| --- | --- | --- |
| 一：视图、轴面与高清裁切 | 视图标题、类型、轴线或面名称、规格目录、逐标签信息、300 DPI 图及定位/来源记录 | 每标签一个构件/组合；不同图仍有重复 |
| 二：图片识别钢材台账 | 图纸与轴面目录统计、各视图台账、长度汇总、端点描述、尺寸引用、UNKNOWN/疑点与代理记录 | 保留第一阶段全部标签；尚未跨视图去重、未展开组合 |
| 三：跨视图匹配与单根统计 | 实体、来源对应、长度采用来源、未知与回退、单根汇总、导出 | 实体先去重，组合件再展开为单根 |

页签的选中状态表示当前查看的阶段；“已确认”等状态表示执行状态，两者含义不同。固定标签台账当前只读，不能在此页面修改规格、数量、长度或所属面。旧任务可能仍展示旧版编辑功能。

`view_tags` 使用完整面名：去掉 `PLAN AT` 或 `ELEVATION ON ALIGNMENT` 等标题前缀，保留项目名称和标高基准。图纸标题所属面由程序补入；邻近轴面是几何提议，不等于端点已经确认。

## 暂停与确认

自动模式无需人工处理疑点即可导出。逐阶段暂停时，完成的阶段进入等待确认，点击继续后执行下一阶段；第三阶段确认后任务完成并显示下载。

UNKNOWN 或回退记录不因确认而自动删除。“允许带未解决问题继续”的兼容字段也不是排除开关。当前新流程没有人工勾选就从汇总删行的机制：

- UNKNOWN 保留数量，长度留空。
- 匹配失败的 FALLBACK 保留为独立观察，可能还包含跨视图重复。
- “完成”表示流程已完成与文件可导出，不表示工程准确率达到某个阈值。

## 重试和重新执行

| 场景 | 行为 |
| --- | --- |
| 失败/中断后重试 | 显式启动；可复用校验通过的阶段结果及请求签名相符的已保存响应 |
| 已完成后从第二阶段重跑 | 保留第一阶段事实包与高清图，第二阶段重新识别，当前第三阶段结果失效 |
| 重跑第三阶段 | 使用第二阶段交付重新匹配；不让第三阶段自由改长 |
| 旧版本页面操作 | 返回 409，刷新获取新阶段版本 |
| 重复确认已确认阶段 | 不重复启动 |

旧目录和导出文件保留在历史中；新一轮完成前，不应把旧下载当作新结果。改变 Prompt、图片、模型参数或事实包可能使缓存不再适用。重跑仍受当前自动/暂停策略影响。

运行或排队期间不能修改阶段状态。服务重启会将未结束任务标为中断，需要显式重试；不要同时启动另一个端口的服务来操作同一数据目录。

## 导出与排查

完成后可下载 `stage_three.xlsx` 和证据 ZIP。Excel 包含实体台账、单根规格长度汇总、展开单根、跨视图对应、原始观察、自动任务审计、未知与回退等工作表。

证据 ZIP 打包该任务目录中的阶段产物、图片、模型响应与日志；上传 PDF 存在相邻的上传目录，不能假定 ZIP 包含原始 PDF。需要搬迁或复核时另行保留源 PDF、数据库与来源目录。

大量 UNKNOWN 时，先检查日志是否存在 HTTP 402（余额不足）或 HTTP 429（限流），再判断尺寸证据是否缺失。账户恢复后，若第一阶段事实包有效，应从第二阶段重新执行，第三阶段随后重新匹配；无需重新上传。已完成后的重跑会重新识别，不等同于仅补齐失败请求。并发按账户实时额度设置，默认 10×5 可能超过服务商的账户限制。

一直等待时，先看模型等待时间和最后一条日志；失败时看任务错误及 `logs/events.jsonl`。API 超时、余额不足、格式无效或预算耗尽可能导致失败或回退，不要反复点击创建重复付费任务。

服务能力可只读核对：

```powershell
Invoke-RestMethod http://127.0.0.1:8120/api/native/capabilities
```

应该返回原阶段页面与两层并发能力。若为 404，核对启动目录和旧进程；不要在正在调用 API 的任务中直接重启。
